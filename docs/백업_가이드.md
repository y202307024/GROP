# GROP 회의 영상 백업

서버가 아니라 **백업 PC**에서 실행합니다. Cloudflare R2 버킷 `grop-meeting-videos`를 이 PC 디스크로 가져옵니다. 올리는 권한은 서버에만 두고, 백업 PC에는 **읽기 전용** 키만 둡니다.

영상 키는 `meeting-videos/{그룹}/{날짜}/{시각}.webm` 입니다. 버킷 전체를 그대로 미러하므로 경로는 R2와 같습니다.

## 폴더

백업 루트 예시는 `D:\grop-r2-backup`(Windows) 또는 `/var/backups/grop-r2`(Mac·Linux) 입니다. 스크립트 안의 경로를 이 PC에 맞게 바꿉니다.

| 폴더 | 역할 |
| --- | --- |
| `current` | 지금 R2와 같은 영상. R2에서 지워지면 여기에서도 빠집니다. |
| `deleted/yyyy-MM-dd` | 그 시각에 R2에서 빠져서 `current`에서 빠진 파일. 실수로 지운 영상을 되돌릴 때 씁니다. |
| `logs` | 실행 로그 |

`deleted`는 `current` **밖**에 둡니다. 안에 두면 다음 동기화가 그 폴더를 다시 지우려 합니다.

## 1. rclone 설치

Windows (관리자 PowerShell):

```powershell
winget install Rclone.Rclone
```

Mac:

```bash
brew install rclone
```

Linux (Debian, Ubuntu):

```bash
sudo apt update && sudo apt install -y rclone
```

설치 확인:

```bash
rclone version
```

## 2. 읽기 전용 토큰

서버 `.env`의 `R2_ACCESS_KEY_ID`는 업로드용입니다. 백업 PC에 복사하지 않습니다.

Cloudflare 대시보드 → **R2** → **API 토큰 관리** → **Account API 토큰 생성**

- 권한: **객체 읽기 전용**
- 버킷: `grop-meeting-videos`만
- 만든 직후의 Access Key ID와 Secret Access Key를 백업 PC에만 적습니다.

계정 ID는 R2 개요의 **계정 세부 정보**에 있습니다. 엔드포인트는 `https://<계정ID>.r2.cloudflarestorage.com` 입니다.

## 3. rclone 연결

원격 이름은 스크립트와 같게 `grop-r2`로 둡니다.

```bash
rclone config
```

1. `n` 새 원격
2. 이름: `grop-r2`
3. 종류: `s3` (Amazon S3 Compliant Storage Providers)
4. 제공자: `Cloudflare`
5. `access_key_id`, `secret_access_key`에 읽기 전용 키
6. `endpoint`에 위 R2 주소
7. `acl`은 `private`

비밀키는 rclone 설정 파일에만 있습니다. Windows는 `%USERPROFILE%\.config\rclone\rclone.conf`, Mac·Linux는 `~/.config/rclone/rclone.conf` 입니다.

연결 확인:

```bash
rclone lsf grop-r2:grop-meeting-videos --max-depth 1
```

버킷 이름이 보이거나, 영상이 있으면 `meeting-videos` 접두사가 나오면 됩니다. 키가 쓰기 권한이 없어도 이 목록 명령은 성공해야 합니다.

## 4. 한 시간마다 맞추기

스크립트가 실행하는 명령은 다음과 같습니다. `DEST`는 `current`, `BACKUP_DIR`은 오늘 날짜의 `deleted` 폴더입니다.

```bash
rclone sync grop-r2:grop-meeting-videos DEST \
  --backup-dir BACKUP_DIR \
  --log-file LOG --log-level INFO
```

`sync`는 백업을 R2와 같게 만듭니다. R2에서 영상을 지우면 `current`에서도 지웁니다. 삭제 요청을 백업에 영원히 남기지 않기 위해서입니다.

바로 지우지는 않습니다. `--backup-dir`가 빠진 파일을 그날 폴더로 옮깁니다. 스크립트는 폴더 날짜가 **7일보다 오래된** `deleted/yyyy-MM-dd`만 지웁니다. 실수로 지운 영상은 7일 안에 그 폴더에서 `current`로 다시 복사할 수 있습니다.

R2로 다시 올리는 작업은 백업 PC에서 하지 않습니다. 그 작업은 쓰기 키가 있는 서버에서만 합니다.

먼저 한 번 수동으로 실행해 로그에 오류가 없는지 봅니다.

Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\path\to\GROP\scripts\backup-r2.ps1
```

Mac·Linux:

```bash
chmod +x /path/to/GROP/scripts/backup-r2.sh
/path/to/GROP/scripts/backup-r2.sh
```

실행 전에 스크립트 상단의 백업 루트 경로를 이 PC 디스크로 바꿉니다.

## 5. 예약

### Windows 작업 스케줄러

백업 디스크를 읽을 수 있는 계정으로 등록합니다. 한 시간마다, 사용자가 로그인하지 않아도 실행됩니다.

명령 프롬프트:

```bat
schtasks /Create /TN "GROP R2 Backup" /SC HOURLY /MO 1 /ST 00:00 /RL LIMITED /TR "powershell -NoProfile -ExecutionPolicy Bypass -File C:\path\to\GROP\scripts\backup-r2.ps1"
```

작업 스케줄러에서 만든 작업을 열어 **가장 높은 수준의 권한으로 실행**은 켜지 않습니다. 백업 폴더 권한만 있으면 됩니다.

### Mac·Linux cron

```cron
0 * * * * /path/to/GROP/scripts/backup-r2.sh
```

매시 0분에 실행합니다. `crontab -e`에 넣습니다. Mac은 전체 디스크 접근이 필요하면 시스템 설정에서 cron을 쓰는 터미널 앱에 권한을 줍니다.

## 6. 백업 PC 보안

- 디스크 암호화를 켭니다. Windows는 BitLocker, Mac은 FileVault, Linux는 LUKS입니다. 암호를 켠 뒤에 백업을 받기 시작합니다.
- 이 PC에는 R2 **읽기 전용** 키만 둡니다. 서버의 쓰기 키, Supabase 서비스 키, Groq 키는 두지 않습니다.
- 로그인 계정을 필요한 사람만 만듭니다. 자동 로그인은 끄고, 자리 비움 때 화면 잠금이 되게 합니다.
- 백업 폴더를 게스트 공유나 공개 클라우드 동기화 폴더에 넣지 않습니다. 네트워크 공유를 쓴다면 백업 담당 계정만 읽게 합니다.
- `rclone.conf` 권한을 소유자만 읽게 합니다. Mac·Linux에서는 `chmod 600 ~/.config/rclone/rclone.conf` 입니다.
- 외부에서 들어오는 원격 데스크톱, SSH 포트는 필요한 주소만 허용합니다. 쓰지 않으면 닫습니다.
- OS 보안 업데이트를 켜 둡니다.
- 백업 PC를 회의 서버와 같은 공개 주소로 열지 않습니다.
